> 版本：v1.0 · 2026-11-08

## 1. 核心洞察：四型是「线」的四种拓扑

你提出的四个概念有一个未被点破的统一性——**没有一个是容器，全是线**：

| 类型 | 拓扑 | 线的作用 |
|---|---|---|
| session | **闭环** | 线首尾自接 = 自我对话 |
| memory | **串联** | 线上挂载离散的点 = 时间印记 |
| document | **承载** | 线作为基准，其上漂浮块面 = 踪迹置于纸上 |
| reason | **汇合** | 两线归一 = 依据推导 |

这比「圆形里放图标」高一个层次：读者记住的不是「哪个图形是哪种节点」，而是**「线在做什么」**。四种拓扑互不混淆，且都能在 12px 下保持轮廓可辨。

**由此得出一条系统规则**：

> **图谱中不出现任何容器轮廓（圆/方边框）。** 节点的"存在感"由踪迹本身 + hover 光晕承担。

这条规则会让图谱显著变"轻"，恰好回应之前"层次弱/单调"的问题——不是靠加装饰，而是靠更克制的语汇。

## 2. 硬约束：小尺寸下的细节存活率

先算清账，否则概念会落空。

当前半径：`session 20 / memory 15 / document 11 / reason 11`（+ 度数增长至多 8）。

| 类型 | 直径 | 你的概念需要在其中放下 | 可行度 |
|---|---|---|---|
| document @ r=11 | **22px** | 基准轨道 + 2 个错开短矩形 + 2 段内嵌曲线 | ❌ 5 元素挤 22px，弧长约 1px，糊 |
| memory @ r=15 | 30px | 主轨迹 + 3 个扁圆珠 + 珠内短横线 | ⚠ 珠子约 4px，内部横线不可见 |
| reason @ r=11 | 22px | 2 条汇聚线 + 交汇点 + 上延线 | ✅ 可读 |
| session @ r=20 | 40px | 连续线 + 2 收束点 + 回卷 | ✅ 可读 |

### 两条对策

**对策 A：半径上调一档**（节点总数实测 4，长期 10–40，空间充裕）

| 类型 | 原 | 新 | 理由 |
|---|---|---|---|
| session | 20 | **24** | 最重，需承载闭环 + 收束细节 |
| memory | 15 | **17** | 珠子需要呼吸空间 |
| document | 11 | **14** | 从 22px → 28px，矩形才有意义 |
| reason | 11 | **14** | 分叉需要角度空间 |

**对策 B：两级复杂度**（这是关键设计，不是妥协）

每个 glyph 定义两层：

- **L1 主轮廓**：常显，占 90% 的可辨识度，必须 12px 下成立
- **L2 细节**：仅在 `:hover`、`.is-active`、或 `viewScale > 1.4` 时淡入

| 类型 | L1（常显） | L2（细节） |
|---|---|---|
| session | 带缺口的环 + 内卷尾 | 两处收束的笔画变细（熔断感） |
| memory | 斜向轨迹 + 3 颗不等距圆珠 | 珠内"有内容"标记 |
| document | 水平基准 + 2 个错开短矩形 | 矩形内的踪迹曲线 |
| reason | Y 形汇合 + 交汇圆点 | 两条来源线的线型差异（实/虚） |

这样小尺寸下不糊，放大或聚焦时细节浮现——**信息随注意力的投入而展开**，这正是"踪迹需要细看"的语义。

## 3. 四型精修

坐标系约定：以节点中心为原点，单位 = `r`（半径）。描边宽度为绝对像素（见 §5）。

### 3.1 session · 接续折迹线

**概念保留**：连续、柔和、两处收束、末端回卷、无尖角。

**精修三点**

1. **用「带缺口的环」而非完整闭环**。完整圆环会与"容器"混淆，也丢掉"流动"感。缺口开在 1–2 点方向（右上），缺口约 50°。
2. **回卷段从缺口的逆时针端向内卷**，止于 `0.30r` 半径处、2 点方向。形成"话说到一半又绕回来"的观感——正是自我对话。
3. **两处收束放在 10 点与 4 点**（对角），让加粗弧段在两处之间交替变细，读起来有"两次起伏"。L2 才显现收束，L1 用均一宽度。

**几何（L1）**
```
外环：半径 0.78r，从 130° 逆时针画到 -40°（留缺口）
回卷：从 -40° 端点，二次贝塞尔内卷到 (0.30r, 2点方向)
线帽：round，无尖角
```

**为什么不用完整螺旋**：1.3 圈螺旋在 48px 内会挤成漩涡，失去"两个表达"的分节感。带缺口的环 + 内尾更克制，也更符合"自我对话"——有开口才成其为对话。

**状态加分项**：hover 时沿路径走一道 `stroke-dashoffset` 流光（1.2s，`prefers-reduced-motion` 下禁用），强化"流动"。

---

### 3.2 memory · 串珠径迹

**概念保留**：主轨迹 + 大小不一的扁圆珠 + 自然疏密。

**精修四点**

1. **轨迹改为**缓弧**而非直线**（从 8 点方向到 2 点方向，弧度 `0.12r` 的弓形）。直线像"连接线"，弧线才像"时间留下的痕"。
2. **三颗珠不等距**，位置按 `-0.72r / -0.10r / +0.58r`（沿轨迹参数 t），刻意不对称——你说的"自然疏密"必须做到**肉眼可见的不规则**才行，等距摆三颗会立刻显得机械。
3. **珠径递进**：`0.16r / 0.24r / 0.19r`。中间最大，暗示记忆有轻重。
4. **"有内容"标记改用「珠心」而非横线**：实心珠 = 有内容，空心珠（仅描边）= 稀疏。这个在 3px 尺寸下依然可辨，横线则不可见。

**为什么放弃"珠内短横线"**：4px 的珠内画一条 3px 横线，视觉上是污点不是信息。改用**填充状态**编码，同样是"有无内容"的语义，但在小尺寸存活。

**状态加分项**：hover 时三颗珠依次 `scale` 弹入（`animation-delay` 0/60/120ms），像"记忆闪回"。

---

### 3.3 document · 轨道刻页

**概念保留**：水平基准轨道 + 上方漂浮 2 个错开短矩形 + 矩形内是踪迹不是文字。

**精修四点**

1. **基准轨道做成「双段」**——中间断开一小截（`0.15r`）。完整一条横线太像下划线；断开后像"被翻过的页脚"。
2. **两个矩形错开**：一个在 `x=-0.42r, y=-0.30r`，另一个在 `x=+0.26r, y=-0.55r`。水平错位 + 垂直错位同时存在，才叫"漂浮"而非"排列"。
3. **矩形尺寸不等**：`0.52r × 0.30r` 与 `0.40r × 0.24r`。大小差异强化"漂浮"的失重感。
4. **矩形内是**一段单弧**（L2）**：每块内画一道 `0.28r` 长的短弧，两块的弧方向相反（一上弯一下弯）。**一条直横线 = 文字；一道小弧 = 笔迹**，这正是你要的"承载的是踪迹不是文字"。

**为什么矩形只留描边不填充**：填充后内部空间被压缩，弧线贴边会脏。描边矩形 + 内部弧 = 干净的"框住的笔迹"。

**状态加分项**：hover 时两块的弧线依次重绘（`stroke-dasharray` 从 0 展开），像"重新翻看"。

---

### 3.4 reason · 分叉收敛径

**概念保留**：两线自下汇聚 + 交汇软圆点 + 单线向上。

**精修三点**（这条概念本身已经最成熟，改动最小）

1. **两条来源线用不同线型**：左实线、右虚线。这是 L2 细节，但**极其重要**——它把"两条独立线索"落地了，否则就是"任意两条线交汇"，语义弱一半。对应现实：日记（实）/ 复盘（虚）。
2. **交汇点用柔和小圆**（`0.11r`，实心），并在 L2 加一圈极淡的扩散描边——"汇聚成一点"的顿挫感。
3. **上升线略作收束**：顶端细分（`0.86×` 起笔宽），暗示"推导趋向结论"。末端不加箭头——箭头太"流程图"，柔化后更像笔势。

**角度**：两来源线与垂直轴各成 `38°`，交汇点在原点，上升线到 `-0.85r`。38° 是经过测试的——太小（<30°）三线会挤在一条上，太大（>50°）像树杈。

## 4. 系统一致性检查

四型放在一起，是否"像一家人"？

| 维度 | 是否统一 |
|---|---|
| 都是**线**为主，无容器 | ✅ |
| 都有**一个"基准"**（session 的环、memory 的轨迹、document 的基线、reason 的上升线） | ✅ |
| 线帽一律 `round`，无尖角 | ✅ |
| 描边宽度两档（主 1.75 / 次 1.1） | ✅ |
| 都有**一处"不完整"**（环形有缺口、轨迹不对称、基线断开、来源线虚实不一） | ✅ ——这是**最关键的一致性**：完整 = 无生命，不完整 = 活的 |

最后一条是我在精修中发现的：你的四个概念里，每一个都天然带着"未完成感"。这不是巧合，而是"踪迹"的本质——踪迹总是残缺的。我把这个提升为系统规则：

> **每个 glyph 必须有一处"不完整"。** 完整即死。

## 5. 描边在缩放下的处理

这是 SVG 方案必须解决的技术点。

**问题**：描边宽度如果随 `viewScale` 线性放大，3x 时线条会粗得像马克笔；如果完全固定，0.4x 时会细到消失。

**方案**：部分反向补偿。
```ts
// viewScale 变化时更新一次容器 CSS 变量（不是每帧）
strokeScale = clamp(1 / Math.pow(viewScale, 0.45), 0.7, 1.5)
```
指数 0.45 意味着：放大 3x 时线条只增粗到 1.64x（而非 3x），缩小到 0.4x 时只减细到 0.66x。

配合 `vector-effect="non-scaling-stroke"` 作为兜底（浏览器支持良好），确保极端倍率下不糊不粗。

标签则用**完全反向**缩放（`1/viewScale`，夹在 0.6–1.6），保证任何倍率下字号恒定可读。

## 6. 交互状态

全部走 CSS 类，不重绘。

| 状态 | 触发 | 视觉 |
|---|---|---|
| default | — | L1 轮廓，透明度 1 |
| `:hover` / `.is-hovered` | JS 命中检测（已有）+ CSS 兜底 | 光晕淡入（`0.35r` 径向渐变）、glyph 放大 1.06、L2 细节淡入、标签强制显示 |
| `.is-active` | 点击选中 | 光晕常驻 + 外圈虚线环（`stroke-dasharray: 3 4`，缓慢旋转 8s）+ 描边加粗到 2.2 |
| `.is-dimmed` | 聚焦模式非目标类型 / 邻接外 | opacity 0.14 |
| `:focus-visible` | 键盘 | 外圈实线焦点环（`--focus-ring` 同款） |

**关于选中态旋转环**：与"静止停帧"原则冲突，但此处**允许**——用户主动选中时正在关注，不是被动浏览。`prefers-reduced-motion` 下静止。

**为什么 hover 用 JS 加类而非纯 CSS**：节点在动，物理引擎的命中检测（`engine.ts` 的 `findNode`，按圆心+半径判定）比 CSS 的几何 hover 更准，判断的是"光标在节点感应区内"；且能与邻接高亮联动。CSS `:hover` 作为快速划过时的兜底。

## 7. 暗色适配（仅新增变量）

SVG 下暗色只需覆盖变量，glyph 的 `<path>` 定义完全复用。

```css
[data-theme='dark'] .graph-stage {
  --ink-stroke:  #e8dfd0;   /* 主描边 */
  --ink-faint:   #8a8078;   /* 次描边、虚线 */
  --soft-fill:   #2a2521;   /* 底填充 */
  --halo:        rgba(224, 112, 90, .22);

  --entity-session:  #e0705a;
  --entity-memory:   #cfaa6a;
  --entity-document: #6d9d97;
  --entity-reason:   #a98cc0;
}
```

**深色下的关键调整**：
- 浅色模式是「深线 + 浅底」；深色模式改「浅线 + 深底」，**线是视觉主体**
- 描边透明度从浅色的 0.85 提到深色的 1.0（深底上低透明度会灰掉）
- 虚线间距放大 20%（深底上密虚线容易糊成实线）

## 9. 决策（已定）

四个取舍按"最优解"全部落定：

| # | 决策 | 理由 |
|---|---|---|
| 1 | **纯踪迹，无底填充** | hover 光晕已经承担了"节点存在感"，再加淡底是冗余；纯线更贴合纸感 |
| 2 | **session 缺口留 1–2 点（右上）** | 与标签位置（正下方）不冲突，连线从左侧与下方进入 |
| 3 | **memory 斜向 32°** | 比 28° 与水平基线对比更明确，又不至于到 35° 时显得倾斜过度 |
| 4 | **reason 虚实差异提升到 L1** | 看不到两条独立来源，这个字形就只是个 Y，语义弱一半 |

### 10.2 实施中踩到的三个坑（都值得记）

**① 光晕用了绝对 px，与字形的 r 单位不符**

字形画在 `<g transform="scale(r)">` 里，坐标单位是"半径"。但光晕写成了
`<circle r="1.9">` 且放在 scaleG **外面** —— 结果只有 1.9px，比字形小一个数量级。

修复：光晕与选中环都移进 scaleG，用 r 单位。

**② `stroke-width` 被 `scale(r)` 放大了 24 倍**

这是最隐蔽的一个。视觉表现是"一团团实心色块"，看起来像填充，实际是
**42px 粗的描边互相重叠**。

修复：给所有描边加 `vector-effect: non-scaling-stroke`。
这条属性恰好也是"任意倍率清晰"的实现基础 —— 线宽不再受任何 transform 影响。

**③ `calc(var(--x) * 1.75px)` 在 SVG `stroke-width` 上失效**

SVG 几何属性对 `calc` + 未定义变量的组合支持不一致，整条声明被丢弃，
线宽回落到默认 1。

修复：改由 JS 按缩放补偿后**直接下发像素值**（`--sw-main: 1.74px`）。

### 10.3 session 尾部的三次返工

| 版本 | 形态 | 问题 |

| v1 | 向内卷的贝塞尔 | 从环内伸出**尖角**，违背"无尖角" |
| v2 | 同心小弧（半径 ≠ 环半径） | 径向**断差**，衔接处仍是折角 |

教训：**曲线衔接的问题必须从切线连续性判断，不能只看端点坐标是否接近。**
